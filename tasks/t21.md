# 2.1 Replay engine

`t21` · status **complete**

Path: [2 Merge divergent stores (0.3)](t20.md)

Canonical replay, decided while building: a one-sided rebase left two copies disagreeing about which task is which id, so both sides' events since the fork are replayed in one chronological order (each side's own order kept, ties by original hash). Both copies then hold identical events, ids and snapshots. Our own events may be rewritten to take their place; diff finds a committed HEAD through replayed_from. Conflicts are per field; --prefer picks the side.
