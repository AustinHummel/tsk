# 12 0.7.0: writer keys and the shared-line merge

`t96` · status **in-progress**

Required by Austin: 'tsk 0.7.0 first' (2026-11-19, in chat to the org's mac-mini side session), on the org's t121 task-ids decision (austin-org, org/org-development/multi-machine-parallelism/decisions/t121-task-ids.md): two machines must write one store without an id or a published outline number ever changing

Two failures to prevent: two copies mint the same id and the merge renames one; a merge with the shared line moves published outline numbers. The design is docs/design-0.7.0.md. The plan (units U1 to U8, sizes, tests) is austin-org, org/org-development/multi-machine-parallelism/tsk-0-7-0-plan-2026-11-19/; U1 to U5 are in this repo. Austin's answers, 2026-11-19: keys are opt-in per store and tsk hardcodes no letters; every store goes to format 3 on its first 0.7.0 write; git's driver does the shared-line merge on a keyed store and refuses during a rebase; no optional unit is built. Done is the release type on the last child.

## Breakdown
