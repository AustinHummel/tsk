# 12.4 The shared-line merge

`t100` · status **todo**

Path: [12 0.7.0: writer keys and the shared-line merge](t96.md)

Fits: merging the shared line without moving any id or outline number it holds, through tsk merge --upstream and through git's driver

U4. Size: 2 to 3 sessions, then 1 blind review session by a fresh agent given the tests and the diff, not the builder's reasoning, who tries to make a published id or number move. Design: docs/design-0.7.0.md. Rules for every unit: one commit, authored Austin Hummel with the Co-Authored-By trailer; each behaviour has an end-to-end test in tests/ that fails without it; run the suite as: env -u TSK_STORE -u TSK_AUTHOR nice -n 10 ~/.cargo/bin/cargo.exe test --locked; update the stated test count in CLAUDE.md; never point a build at this store or the org's.
Builds, as the design note's 'The shared-line merge', 'The report', 'The pending marker' and 'The git merge driver' say: tsk merge <theirs> --upstream keeps their line hash for hash and replays our events not on it (by replayed_from identity) after it in our order; our new tasks and adoptions take the next positions; nothing of ours left is a fast-forward; field conflicts stop it as now. On a keyed store a merge that came through git settles this way. git-setup registers the driver with %P; on a keyed store the driver refuses during a rebase (rebase-merge or rebase-apply under git rev-parse --git-path), leaving %A untouched, exit 1, one sentence with the way out. The report (each number of ours that moved; each leaf with status on both sides and the status it ends in) goes to text, --json and the Merged event's message. A pending marker whose target is already merged is cleared.
Tests (tests/merge.rs): a_published_id_and_number_survive_a_merge_with_an_older_unpublished_event; theirs_keeps_every_hash; nothing_unpublished_is_a_fast_forward; the_report_names_every_number_of_ours_that_moved; status_on_both_sides_is_reported_with_the_status_it_ends_in; merging_twice_changes_nothing; the_driver_path_on_a_keyed_store_keeps_theirs; the_driver_refuses_during_a_rebase_on_a_keyed_store (both backends; an unkeyed store still merges); apply_and_prune_then_merge (if a prune before the fork breaks replay, the merge refuses in a sentence and it is listed as a limit); a_pending_marker_already_merged_is_cleared. The 7 existing merge tests pass unchanged.
